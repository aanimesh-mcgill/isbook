Chapter 2 of 18

Write a page with HTML and CSS

Build one page a visitor could read: a heading, a sentence, a picture, a list, and a link. The tag explanations follow HTML Crash Course For Absolute Beginners. That video stays on HTML5 and shows one style rule inside the page. The CSS section after the tags is the rest: what a stylesheet is, how pages were colored before stylesheets, and the places a rule can live. This project keeps the rules in style.css.

A classmate should understand the event from the page alone.

Inputs
The event name, one sentence, three things to bring, one image file, and one outside address.
Expected output
A browser page with those parts, and colors that come from a stylesheet.
Rules
Use the tags below for the jobs they actually do. The image needs alternative text. The link needs an address.

What the tags do

HTML stands for hypertext markup language. It is not a programming language. A programming language can say “if this is true, do that.” HTML cannot. It marks the parts of a page so a browser can show a heading, a paragraph, a bullet list, or a picture. JavaScript, later in this book, is the language that can decide a winner. Every site a browser shows is HTML by the time it arrives, even when another language built that HTML.

You need two tools: a text editor and a browser. The computer does not matter. The file must end in .html, or the browser will not treat it as a page. Name the homepage index.html. A host looks for that name first. You can write and open the file on this computer before anyone else can see it. Putting it on a public address comes in chapter 5.

Work in public/index.html unless a block says otherwise. If you do not want to type, use Copy, paste, save, and reload. Each block tests one idea. The picture under the block is that page after the paste, added to what was already there. The complete files are at the end.

Open the file before the first paste

The pictures in this chapter are a browser drawing your file. Open that file once, on the first block. Every block after that is a reload of the same tab.

  1. Create public/index.html if it is not there yet. Paste the first block and save.
  2. In Explorer, right-click index.html and choose Reveal in File Explorer. On a Mac, choose Reveal in Finder.
  3. Double-click the file. You can also drag it into Chrome or Edge.

The address starts with file:///. The browser is reading a file on this computer. After each later save, reload the tab. A tab you do not reload still shows the previous save. The next chapter reads that address and explains why a classmate cannot open it.

Plain text still shows

A tag is the building block. The name sits between < and >. Most tags come in a pair: a start tag, the words, then an end tag that begins with </. Before any of that, confirm the browser will show text with no tags at all. Paste only these words, save, and open the file. The page should say Campus game night, in the browser’s ordinary text, with no large heading.

public/index.html · nothing but words
Campus game night

Start the document

<!doctype html> is the first line. It is a declaration, not a tag: there is no end tag and nothing inside it. It tells the browser this file is HTML5. Older doctypes were long and easy to get wrong. Paste it once, at the top, and replace the plain text with the shell below.

First line of public/index.html
<!doctype html>

html wraps the whole document. lang="en" says the words are English. Inside it, head and body are the two regions. head is not drawn on the page. It holds the tab title, and later the link to a stylesheet. title is the words on the browser tab. body is what a person sees: headings, text, and images. Paste this whole shell, save, and reload. The page should show a large heading, and the tab should say Campus game night. If the body is empty, the page stays blank and the tab still shows the title.

public/index.html · document shell
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Campus game night</title>
</head>
<body>
  <h1>Campus game night</h1>
</body>
</html>

meta charset tells the browser how letters and punctuation are stored. Leave it in head. Without it, an apostrophe or an accent can turn into the wrong character. viewport tells a phone to use the device width. Paste it under the charset line. On a narrow window the page should fit instead of looking like a tiny desktop page.

Inside head, under the charset line
<meta name="viewport" content="width=device-width, initial-scale=1">

In Chrome, Ctrl+U shows the HTML the browser read. On a Mac that shortcut is Command+Option+U. F12 opens the developer tools. The Elements tab is the HTML again. Hover a line there and the matching part of the page lights up. You can edit that panel, but the edit lasts only until you reload. The file is what gets saved.

A comment is for you, not for the visitor. It starts with <!-- and ends with -->. Paste this above the heading, save, and reload. The sentence inside the comment should not appear on the page.

Inside body, above the heading
<!-- The heading is the event name. -->

The visible parts

The browser already has a little styling of its own, called the user-agent stylesheet. You have not written CSS yet. An h1 is still large, and a paragraph still has space above and below it, because the browser supplies that. CSS can change those sizes later. Use a heading for its rank, not as a way to pick a font size.

There are six heading ranks, h1 through h6. h1 is the largest. Use one h1 for the page. The words go between the start tag and the end tag. The shell already has the h1. If you removed it, paste this back inside body.

Inside body
<h1>Campus game night</h1>

h2 is the next rank. Paste it under the h1. Reload. It should be smaller than the h1, with space between them. h3 through h6 keep stepping down. You do not need those on this page.

Under the h1
<h2>Bring</h2>

p is a paragraph. It is a block: it starts on a new line and can use the width of the page. Paste two of them. Reload. The second sentence should sit under the first, not beside it. The gap between them is the browser’s default margin, space outside the paragraph.

Under the h2
<p>One short game for people waiting between events.</p>
<p>It takes a few minutes.</p>

br is a line break inside one paragraph. It is one tag, not a pair, because it has nothing inside it. In HTML5 you write <br>. The older <br /> form is not required. Paste this in place of the two paragraphs if you want both sentences in one paragraph, with the second on the next line.

One paragraph, two lines
<p>One short game for people waiting between events.<br>It takes a few minutes.</p>

An inline tag does not start a new line. It uses only the width of its words. strong means those words matter. The browser draws them bold unless CSS says otherwise. That is the meaning, not a font button. The old b tag only asked for bold and is not the one to use. em means emphasis. The browser draws it italic. Paste this as another paragraph. “Here” should be heavier, and “few” should be italic, and both should stay in the sentence.

Another paragraph
<p>The rules page will live <strong>here</strong>. It takes a <em>few</em> minutes.</p>

ul is an unordered list: bullets. Each li is one item, and the items sit inside the list. The browser indents the list. Paste this under the heading “Bring”. Reload. You should see two bullets.

Under the h2
<ul>
  <li>A phone with a browser</li>
  <li>A few minutes</li>
</ul>

ol is an ordered list. The markup is the same, with ol instead of ul. Paste this under the bullets. Reload. The two steps should be numbered 1 and 2, not bulleted.

Under the ul
<ol>
  <li>Open the file</li>
  <li>Reload after each save</li>
</ol>

Links and images

An attribute adds a fact to a start tag. It is a name, then =, then a value in double quotes. Single quotes also work. Double quotes are the usual choice. a is a link, and it is inline, so it stays in the sentence. href is the address. The words between the tags are what the person clicks. href can be another file next to this one, such as about.html, or a full address on another site. Paste this, reload, and click the words. The browser should leave your page. Use Back to return.

A link
<p><a href="https://firebase.google.com/docs/hosting">What web hosting is</a></p>

target="_blank" is optional. It opens the address in a new tab, so the reader still has your page. Use it for someone else’s site. Do not use it for a link to another page of your own site, or every click piles up a tab. Paste this in place of the link above. Reload and click. The hosting docs should open in a new tab, and your page should still be there.

The same link, in a new tab
<p><a href="https://firebase.google.com/docs/hosting" target="_blank">What web hosting is</a></p>

img is a picture. It is inline, and it has no end tag, because it does not wrap other content. An img with no src has nothing to load. src is the file, written relative to index.html. A file in the same folder is just the file name. A file in a folder named images would be images/mark.svg. alt is the text if the picture cannot be found. width is how wide to draw it, in pixels. Leave height off. The browser then keeps the proportions. Setting both width and a short height stretches the picture. Save the image file first, then paste the tag, then reload. You should see the picture.

public/mark.svg · save this file, then use the img tag
<svg xmlns="http://www.w3.org/2000/svg" width="160" height="80" viewBox="0 0 160 80">
  <rect width="160" height="80" rx="8" fill="#2a211c"/>
  <text x="80" y="48" text-anchor="middle" fill="#ffb77d" font-family="Georgia, serif" font-size="28">RPS</text>
</svg>
Inside body, above the list
<img src="mark.svg" alt="The letters RPS on a dark card" width="160">

A JPEG already on your computer

The SVG above is text you can paste. A photograph is a file. It usually ends in .jpg or .jpeg.

  1. Find the picture in Pictures, Downloads, or on the Desktop.
  2. On Windows, show the extension. In File Explorer choose View, then Show, then File name extensions. You need to see .jpg. A name that ends in .jpg.txt is not a picture.
  3. On a Mac, in Finder choose Settings, then Advanced, and turn on “Show all filename extensions.”
  4. Copy that file into public, next to index.html. A file that stays in Pictures is invisible to the page. The browser looks in the page’s folder.
  5. Rename the copy to photo.jpg. The name in src must match, including the extension. Avoid spaces in the name.

Paste this under the SVG image. Save and reload. The flower should appear. If you see the alt words instead, the file is not beside index.html, or the names differ.

Under the SVG image · photo.jpg is in the same folder
<img src="photo.jpg" alt="A red flower saved next to index.html" width="240">

A picture that already has a web address

You do not copy this file into public. On a web page, right-click the picture and choose Copy image address. Do not choose Copy image. The address starts with https://. Paste that address into src. When your page opens, the browser asks the other computer for the picture. This works only while you are online. If the address breaks, the alt text shows, the same as a missing file in your folder.

Paste this under the flower. Reload. A landscape should appear. The sample address below is a JPEG stored on another site, not in your project.

Under the local photo · the file stays on the other site
<img src="https://picsum.photos/id/1015/320/200.jpg" alt="A fjord seen from a cliff" width="320">

To see alt work, change the SVG’s src to missing.svg, save, and reload. The page should show a broken-image mark and the words “The letters RPS on a dark card”. Change src back to mark.svg and reload. The card should return. You can also wrap the SVG image in a link. Paste this in place of that image. Click the card. The browser should open the image file itself. Use Back to return to the page.

The picture as a link to its own file
<a href="mark.svg"><img src="mark.svg" alt="The letters RPS on a dark card" width="160"></a>

CSS

CSS stands for cascading style sheets. HTML names the parts of the page: a heading, a paragraph, a list, a picture. CSS sets how those parts look: color, typeface, and space. A rule has a selector and declarations. body selects the body. color is the text color. background is the page color. font-family is the typeface. margin is space outside the element. CSS has no “if this, do that.” That decision waits for JavaScript.

The two files fit together. The browser reads the HTML, builds the parts, then paints them with CSS. Delete the stylesheet and the words, lists, and pictures remain, in the browser’s own colors. Change the stylesheet and the same HTML looks different. One stylesheet can serve every page that links to it. Chapter 6 adds rules to the file you create here.

The browser already paints with a built-in stylesheet, the user-agent stylesheet from earlier in this chapter. Your rules replace the properties they name. The heading stays a heading. Its size and color become whatever you set.

How pages looked before stylesheets

In the 1990s the look lived in the HTML. A font tag set the color and the typeface of the words it wrapped. A body tag could carry bgcolor and text. align="center" and a center tag moved things around. People also used tables to build columns, which mixed the layout into the structure. A table is for rows of data. This page does not need one.

HTML5 removed font, center, and those presentational attributes. A current browser may still draw a font tag. The finished page leaves it out. Paste this in place of the heading, save, and reload. The heading should turn brown, in Georgia, and the rest of the page should stay as it was.

Replace the h1 · the old way, for one reload
<h1><font color="#b45309" face="Georgia">Campus game night</font></h1>

Put the plain heading back when you have seen it. Save and reload. The heading should return to the browser’s ordinary large black text.

The heading to keep
<h1>Campus game night</h1>

Where a rule can live

A current page writes that look in CSS. The same rule can sit in three places. You can also pull a second CSS file in from the first. Try each place, reload, and then keep only the last one.

On the element

A style attribute on a start tag styles that one element. Paste this in place of the heading, save, and reload. The heading should turn brown again, in Georgia. The paragraphs stay in the browser’s typeface. Use an attribute when one element needs a one-off look, or in an email that cannot load a separate file. On this page it gets in the way: the color is stuck to the tag, and a later rule in a file loses to it.

Replace the h1 · inline, for one reload
<h1 style="color: #b45309; font-family: Georgia, serif;">Campus game night</h1>

Put the plain heading back, save, and reload, so the next step can change the heading.

In the same file

A style element in head holds rules for this page only. The crash course uses this. Paste it under the title, save, and reload. The page background should turn dark, the text light, and the link a different color. The words in the HTML did not change.

Inside head, under the title · for one reload
<style>
body {
  margin: 0;
  background: #1a1c1f;
  color: #f4efe8;
  font-family: Georgia, serif;
}

main {
  max-width: 36rem;
  margin: 2rem auto;
  padding: 1rem;
}

a {
  color: #ffb77d;
}
</style>

If the heading is still brown, the style attribute is still on it. An inline attribute beats a rule in this block for that property. Delete the attribute and reload.

A style element is useful while you are testing one page. A second page cannot see it. Delete the whole style element before the next step. Reload. The page should return to the browser’s own colors.

In a separate file

This is the place this project keeps. link rel="stylesheet" in head loads style.css, a file beside index.html. Paste the link, save, and reload before the CSS file exists. The colors should not change yet.

Inside head
<link rel="stylesheet" href="style.css">

Save the same rules as public/style.css. max-width caps how wide main can grow. Reload. The page should look like the style element did. The difference is where the rules live: one file, shared by any page that links to it. Chapter 6 edits this file again.

public/style.css · paste, save, reload
body {
  margin: 0;
  background: #1a1c1f;
  color: #f4efe8;
  font-family: Georgia, serif;
}

main {
  max-width: 36rem;
  margin: 2rem auto;
  padding: 1rem;
}

a {
  color: #ffb77d;
}

The a rule changes only links. After you reload, the hosting link should be a different color from the paragraph.

A CSS file can pull in another one with @import url("other.css"); at the top of the file. That is a fourth place for rules. The browser waits on that import before it finishes the first file. This project uses link and leaves @import out.

When two of your rules set the same property, the more specific one wins. An inline style attribute beats a selector in a style element or in style.css. Between two equal selectors, the one that comes later wins, so a style element after the link tag beats the file. This page uses the file alone, so there is one place to look.

A button can sit on the page now, and it will do nothing. HTML can draw the control. A click needs JavaScript, which starts in chapter 11. Paste this under the lists if you want to see that limit. Reload and click Rock. The page should not change.

Under the lists
<p><button type="button">Rock</button></p>
