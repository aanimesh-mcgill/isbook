Make the game one page with three views

The game is one scrolling page. Rules, play, and recent rounds share one score. An SPA keeps that sharing and shows one view at a time, without asking the server for a new HTML file.

The score must survive a look at the rules.

Inputs
The finished game, and three names: rules, play, rounds.
Expected output
A nav. One view visible. The address ends in #play, #rules, or #rounds. Back returns to the previous view. The score is unchanged.
Rules
Do not add a Firebase rewrite. The hash stays in the browser. The server still receives a request for index.html.

What changes, and what stays

A multi-page version would be rules.html, play.html, and rounds.html. Each click would be a new request, a new document, and a new run of the script. playerScore would start at 0 again.

An SPA is one document. The script keeps running. You hide two sections and show one. The server's job does not change: it still sends index.html, style.css, and script.js.

Use this for the game. The three views are one activity.

Leave the textbook as separate files. A chapter link should open that chapter even when the script does not run. One broken script in an SPA takes every view with it. The first download is also the whole app, which is fine for three short views and a poor trade for a long book.

Add the nav and the three sections

Put a nav under the heading. Wrap the rules, the buttons, and the round list in sections. hidden on play and rounds means the first paint, before the script runs, shows the rules. The script then shows the view named in the hash, and play when the hash is empty.

public/index.html · replace the inside of main
<h1>Rock · Paper · Scissors</h1>
<nav>
  <a href="#rules">Rules</a>
  <a href="#play">Play</a>
  <a href="#rounds">Rounds</a>
</nav>
<section id="rules" data-view="rules">
  <p>Choose one move each round. Identical moves tie.</p>
  <ul>
    <li>Rock beats scissors.</li>
    <li>Paper beats rock.</li>
    <li>Scissors beats paper.</li>
  </ul>
</section>
<section id="play" data-view="play" hidden>
  <p>
    <button type="button" data-move="rock">Rock</button>
    <button type="button" data-move="paper">Paper</button>
    <button type="button" data-move="scissors">Scissors</button>
  </p>
  <p id="result" role="status">Choose a move.</p>
  <p id="score">You: 0 · Computer: 0 · Ties: 0</p>
  <p><button type="button" id="reset">Reset score</button></p>
</section>
<section id="rounds" data-view="rounds" hidden>
  <h2>Recent rounds</h2>
  <ol id="history"></ol>
</section>

Swap the view when the hash changes

Paste this above the click listeners. href="#play" does not request a new file. The browser updates the hash and fires hashchange. showView sets hidden on the other sections. The score variables sit outside that function, so they stay.

Add to public/script.js, above the click listeners
function showView(name) {
  for (const view of document.querySelectorAll("[data-view]")) {
    const on = view.dataset.view === name;
    view.hidden = !on;
  }
  for (const link of document.querySelectorAll("nav a")) {
    const on = link.getAttribute("href") === "#" + name;
    if (on) link.setAttribute("aria-current", "page");
    else link.removeAttribute("aria-current");
  }
}

function viewFromHash() {
  const name = location.hash.replace("#", "");
  if (name === "rules" || name === "rounds") return name;
  return "play";
}

window.addEventListener("hashchange", () => showView(viewFromHash()));
showView(viewFromHash());

Reload. The address should end in #play, and the buttons should be the only view. Click Rules. The hash becomes #rules, the buttons disappear, and no new document loads. Play a round, open Rules, then Play again. The score should still be there. Use the browser Back button. The previous view should return.

A path such as /play would need the Firebase rewrite you turned off. The hash avoids that. A missing style.css is still a 404.
