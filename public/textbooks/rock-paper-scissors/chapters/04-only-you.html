See why nobody else can open it

In chapter 2 you opened index.html and reloaded it after each paste. The address in that tab starts with file:///. This chapter reads that address, then follows the kind of address a classmate can open.

What that file address is doing

The browser is reading a file on this computer. Reload the tab after every save. A tab you do not reload still shows the previous save.

You should see the heading, the sentence, the pictures, the lists, and a link. Click the link. It should leave your page and open the hosting documentation. Use Back to return.

If a picture is broken, src does not match a file sitting next to index.html. If the page is black text on white, style.css did not load. Check the link href and the file name.

Try to share the address

Copy the file:/// address and send it to another person, or open it on a phone that does not have this folder. It fails. That address points at a disk the other person does not have.

Why sending one file is not enough

If you email only index.html, the message does not include style.css or mark.svg. Their browser will show the words and a broken picture, without your colors. A page is a set of files that refer to each other by name.

A client and a server

Two programs do the work of a web page. The browser is the client. It asks for a resource. The server is a program on a computer that stores files and answers those asks. Your file:/// tab has a client and the disk in the same computer. A classmate's browser has a client, and it has no path to your disk. It needs a server that is willing to answer.

Hosting means putting the files on a server and giving that server a public address. The next two chapters do that with Firebase Hosting. You do not write the server program. You do need to know the conversation it has with the browser.

How a page crosses the internet

You type an address or click a link. The host name in that address, such as firebase.google.com, is a name for people. The browser asks the Domain Name System, DNS, to turn that name into an IP address, the numeric address of the server. It then connects to that computer. HTTPS uses port 443. Plain HTTP uses port 80. A port is the door on that computer for this kind of conversation.

The browser sends a request. The server sends a response. The browser reads the HTML and then sends another request for each file the page names: style.css, mark.svg, photo.jpg. The fjord in chapter 2 arrived this way. The browser requested an https:// address, and another site responded with the JPEG.

The response starts with a status code. 200 means the server sent the resource. 404 means the server has nothing at that path. In Chrome, F12 and the Network tab list every request from the last reload. Each row is one request and the response that came back.

The parts of a URL

A URL is the address of one resource. The link on your page is one:

https://firebase.google.com/docs/hosting

  • https is the scheme. It names how the client and the server will talk.
  • firebase.google.com is the host. It names which server.
  • /docs/hosting is the path. It names which resource on that server.

A question mark starts a query, extra detail for that request, as in ?v=2. A hash starts a fragment, a spot inside the page, as in #rules. The fragment stays in the browser. The request that reaches the server ends at the path and the query.

The address in your tab is a URL as well. The scheme is file. There is no host. The path is a folder on this computer, for example file:///C:/Users/you/campus-game/public/index.html.

The request and the response

The request is a short text message. GET asks the server to send a resource. The path says which one. The Host line says which site, because one computer can answer for many names.

GET /docs/hosting HTTP/1.1
Host: firebase.google.com

The response names a status and the type of the bytes that follow. Then the page itself.

HTTP/1.1 200 OK
Content-Type: text/html

A click on your page causes several of these pairs: one for the HTML, one for the stylesheet, one for each image. The browser draws the page after those responses arrive.

HTTP and HTTPS

HTTP is that language: the method, the path, the headers, the status, and the body. Both http:// and https:// use it.

With http://, the request and the page travel as readable text on port 80. Anyone on the path between the two computers can read them. The browser also has no proof that it reached the host named in the URL.

https:// is HTTP inside TLS, on port 443. Before the page is sent, the two sides agree on a key, and the server presents a certificate for the host name. The request and the response are encrypted. The lock in the address bar is the browser's check of that certificate. Firebase Hosting answers on https://. The public link you test in the hosting chapter will start that way.

A file:/// address never makes this trip. A public page has an https:// URL, a server that stores the files, and a response for every request. The next two chapters put your folder on that kind of server.
