Change the project with Git

Every change from here to the end of the book uses the same loop. The video does that loop in Source Control. The commands do the same loop in the terminal. Git is how the project moves forward. Firebase is how a visitor sees the commit you decided to publish.

The loop

  1. Edit the files in public.
  2. Open index.html locally, or reload it, and check the behavior.
  3. Run git status and git diff. Read the lines.
  4. git add only the files that belong in this change.
  5. git commit with a sentence about the behavior, not a list of file names.
  6. git push.
  7. When the public link should match, firebase deploy --only hosting and open that link.
Terminal · after you have checked the page
git status
git diff
git add public/index.html
git commit -m "Rename the event heading"
git push
firebase deploy --only hosting --project YOUR_PROJECT_ID

Do it once on the heading

Change the h1 text to Campus game night if you already renamed it, or to Friday game night if you have not. Follow the loop. On GitHub, open public/index.html and confirm the new heading. Then reload the Hosting URL and confirm the same heading.

If git diff shows a change you did not mean, fix the file before you add it. A commit records what you staged, not what you hoped you staged.

Read the gutter and the diff

Open public/index.html. Change the heading. In the strip left of the line numbers, the edited line should turn blue. Add a blank line under the heading: that new line should be green. Delete a blank line and a red arrow should mark the gap. Put the deleted line back before you commit.

Open Source Control and click the file under Changes. The editor opens a diff: the old lines on one side, the new lines on the other. In the upper right of that editor, switch between the side-by-side view and the inline view. Inline stacks the old and new lines in one column. You can type in the diff. A change you type there is a change to the file.

The icons on that file open it, discard the uncommitted edits, or stage them. Discard throws away edits that are not in a commit. It does not delete a commit. The icons on the Changes heading discard every unstaged edit, or stage every file. Stage only the heading change.

Put the heading on its own branch

A feature belongs on a branch, so main stays the version you already published. Open the Command Palette and run Git: Create Branch. Name it heading. The status bar should say heading. Commit the heading there with the check mark and the message Rename the event heading.

Click the branch name in the status bar and switch to main. The heading in the file should be the old one. heading kept the new text. main did not.

To bring it across, stay on main. In Source Control open the ... menu, choose Branch, then Merge Branch, and choose heading. The heading in the file should now be the new one, and the status bar should still say main.

Terminal · the same branch, switch, and merge
git switch -c heading
git add public/index.html
git commit -m "Rename the event heading"
git switch main
git merge heading

After git switch main, and before the merge, the heading in the file is the old one. After git merge heading, it is the new one.

Push, pull, and sync

Push uploads commits. Pull downloads commits that are on GitHub and not on this computer. Sync does pull, then push. Use Sync when a classmate may have pushed while you were editing. The status bar shows the branch and the sync action.

Terminal
git pull
git push

If you and a classmate changed the same lines, Git stops. It does not guess. The file contains both sides, with markers like these:

Conflict markers · delete the markers and keep one heading
<<<<<<< HEAD
Friday game night
=======
Campus game night
>>>>>>> heading

Keep the heading you want, delete the three marker lines, save, stage the file, and commit. That commit is the resolution. Do not leave the markers in the page a visitor can open.

Clone a repository you do not have

On GitHub, open the repository, click Code, and copy the HTTPS address. In the Command Palette run Git: Clone, paste the address, and choose a folder. When it asks to open the cloned repository, open it. You should see the same files, and the status bar should say main.

Terminal · the same clone
git clone https://github.com/YOUR_NAME/campus-game.git

In Explorer, open the Timeline view at the bottom of the sidebar while index.html is selected. It lists the commits that touched that file, and the local saves. The graph in Source Control lists commits for the whole repository. Git blame, from the same menus, names the commit that last changed a line.
