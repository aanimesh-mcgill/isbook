Chapter 1 of 15

Explain the rules before play

A new player needs to learn the game without asking the event staff.

Inputs
The game’s name and rules supplied by the event team.
Expected output
A browser page with a title, one instruction, and a list of winning pairs.
Rules
Use all three pairs and explain ties. The page must open from the extracted folder.

Build it step by step

Create the page

Open a new practice folder in a plain-text code editor. Create index.html and save it using the complete file below. Open it in your browser. After each edit, save in the editor and reload in the browser.

index.html · complete file
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>Rock · Paper · Scissors</title>

</head>
<body>
<main class="game">
  <h1>Rock · Paper · Scissors</h1>
  <p>Choose one move each round. Identical moves tie.</p>
  <ul>
    <li>Rock beats scissors.</li>
    <li>Paper beats rock.</li>
    <li>Scissors beats paper.</li>
  </ul>
</main>
</body>
</html>

Read the structure

The doctype selects modern HTML rendering. The head contains metadata such as the browser tab title and the viewport setting for phones. The body contains visible content. A start tag and end tag mark the extent of most elements. The list groups three sibling items. View Source shows saved markup. Inspect shows the browser’s live representation, called the DOM.

Check the file address

With the page opened directly, the address begins with file:. The browser reads the file from disk. An address beginning with https: asks a web server for a resource. You will compare those paths in the server lab.

Capture and confirm a player’s choice

Players need to know the application received their move.

Inputs
A click or keyboard activation of Rock, Paper, or Scissors.
Expected output
A message such as “You chose paper.”
Rules
Only one message changes for each activation. The choices must work with Tab and Enter.

Build it step by step

Add genuine controls

Replace the “Play controls arrive” paragraph with the buttons and status paragraph. The visible button label is for the player. data-move is the program’s value. role="status" allows assistive technologies to announce text changes.

index.html · inside main
<div class="choices" aria-label="Choose a move" role="group">
  <button type="button" data-move="rock">Rock</button>
  <button type="button" data-move="paper">Paper</button>
  <button type="button" data-move="scissors">Scissors</button>
</div>
<p id="result" role="status">Choose a move.</p>

Connect a script

Add <script src="script.js" defer></script> in head. defer waits for parsing before the script looks up the buttons. First wire one button using the file below. querySelector returns the first matching element. The listener receives a function value and calls it later. play receives a string parameter. textContent writes plain text into the DOM.

script.js · first working checkpoint
const result = document.querySelector("#result");
const rock = document.querySelector('[data-move="rock"]');

function play(player) {
  result.textContent = `You chose ${player}.`;
}

rock.addEventListener("click", function () {
  play(rock.dataset.move);
});

Wire all three buttons

Replace the single-button lookup and listener with the loop below. Keep result and play. querySelectorAll gives the matching elements. A for…of loop reads each in order and registers its listener. The loop executes on load. The listener body executes when its button is activated. dataset.move reads data-move from the current button.

script.js · replace single-button wiring
for (const button of document.querySelectorAll("[data-move]")) {
  button.addEventListener("click", function () {
    play(button.dataset.move);
  });
}

Chapter 4 of 15

Give the computer a move

One student should be able to play without a partner.

Inputs
A player action and one random value in the interval [0, 1).
Expected output
The player’s move and a valid computer move.
Rules
Choose independently each round. Each of the three moves has an equal chance under a uniform draw.

Build it step by step

Store the allowed choices

Create logic.js beside script.js and load it with defer before script.js. A JavaScript array keeps values in order. Brackets around a number select the value at that position, starting at zero. The moves array has length 3 and last index 2.

logic.js · complete file
const moves = ["rock", "paper", "scissors"];

function chooseComputerMove(random = Math.random) {
  const index = Math.floor(random() * moves.length);
  return moves[index];
}

Turn a sample into a position

Multiplying by length gives a value from zero up to 3, excluding 3. Math.floor rounds down. Each interval is one-third of the starting range. With no argument, the function calls Math.random. The optional argument is a function that can supply a known sample for debugging and testing.

Browser Console · try known samples
chooseComputerMove(() => 0.2)
chooseComputerMove(() => 0.5)
chooseComputerMove(() => 0.9)

Display both moves

In script.js, replace play with the following. A const binding keeps one value for that call. The next activation creates a new call with a new local computer value. A template literal uses backticks and inserts expressions at dollar-brace markers.

script.js · replace play
function play(player) {
  const computer = chooseComputerMove();
  result.textContent =
    `You chose ${player}. Computer chose ${computer}.`;
}

Chapter 5 of 15

Turn the game rules into a decision

After each round, the player needs a clear result they can verify.

Inputs
One valid move from the player and one from the computer.
Expected output
Exactly one result from the player’s point of view: win, lose, or tie.
Rules
Equal moves tie. Apply all three winning pairs. Each other valid pair loses.

Build it step by step

Specify the full decision table

Read the row as the player and the column as the computer. With three inputs on each side there are nine combinations. Writing the expected table before coding gives you a separate reference when you review the implementation.

Implement the rule

Add the function after chooseComputerMove. Each expression with === compares two values. && requires both comparisons in a pair to be true. || accepts any of the three winning pairs. return ends the function immediately. The final return covers all remaining valid pairs. This function assumes a valid move from each caller.

logic.js · append function
function decideWinner(player, computer) {
  if (player === computer) {
    return "tie";
  }
  if ((player === "rock" && computer === "scissors") ||
      (player === "paper" && computer === "rock") ||
      (player === "scissors" && computer === "paper")) {
    return "win";
  }
  return "lose";
}

Connect the rule to the screen

In play, assign the result of decideWinner(player, computer) to outcome and include it in the status. The rule function returns a value without writing to the page. The event handler handles display. Use the Console to test exact pairings without waiting for random draws.

script.js · replace play
function play(player) {
  const computer = chooseComputerMove();
  const outcome = decideWinner(player, computer);
  result.textContent =
    `You chose ${player}. Computer chose ${computer}. Result: ${outcome}.`;
}

Chapter 6 of 15

Keep score and start over

Visitors want to see how they performed over several rounds and reset for the next player.

Inputs
A completed round or activation of Reset score.
Expected output
Three running totals and a reset message when requested.
Rules
A win, loss, or tie changes exactly one counter. Reset clears all counters. Reloading starts a fresh session.

Build it step by step

Separate values from their display

Add the score and reset controls after the result. The paragraph shows zero initially. JavaScript stores the values so it can add to them later. let allows reassignment, and += 1 adds one to the existing number.

index.html · inside main
<p id="score">You: 0 · Computer: 0 · Ties: 0</p>
<button type="button" id="reset">Reset score</button>

Update state, then render it

Add these declarations above play. State means values that survive from one event to the next while the page is open. Keep the counters outside play so each invocation can update the previous totals. renderScore projects values onto the page. Call updateScore(outcome) then renderScore() immediately after deciding the outcome.

script.js · score functions
let playerScore = 0;
let computerScore = 0;
let ties = 0;

function updateScore(outcome) {
  if (outcome === "win") {
    playerScore += 1;
  } else if (outcome === "lose") {
    computerScore += 1;
  } else {
    ties += 1;
  }
}

function renderScore() {
  document.querySelector("#score").textContent =
    `You: ${playerScore} · Computer: ${computerScore} · Ties: ${ties}`;
}

Handle reset as a separate event

Add a listener after the move listeners. Change the underlying values before rendering. Check the reset by playing another round immediately afterward. The sum of the three counters must equal the number of rounds since reset.

script.js · append reset listener
document.querySelector("#reset").addEventListener("click", function () {
  playerScore = 0;
  computerScore = 0;
  ties = 0;
  renderScore();
  result.textContent = "Scores reset. Choose a move.";
});

Chapter 7 of 15

Show the last five rounds

The player wants to check how the score was reached.

Inputs
A completed round with two moves and an outcome, or a reset.
Expected output
An ordered list of up to five rounds, newest first.
Rules
Discard the oldest displayed round when the sixth arrives. Keep cumulative scores. Reset also clears the list.

Build it step by step

Give the list an HTML home

After the reset control add the history section. Start with an empty ordered list. Add the script below after renderScore and before play.

index.html · inside main
<h2>Recent rounds</h2>
<p>Newest first. Up to five rounds are shown.</p>
<ol id="history"></ol>

Store each round as a record

The array stores one object per round. The properties name the parts of that record. The shorthand { player, computer, outcome } creates properties with the names and values of the parameters. unshift inserts at index zero, and pop removes the last element. const prevents reassigning history while allowing changes to its contents.

script.js · history functions
const history = [];

function addRound(player, computer, outcome) {
  history.unshift({ player, computer, outcome });
  if (history.length > 5) {
    history.pop();
  }
}

function renderHistory() {
  const list = document.querySelector("#history");
  list.replaceChildren();
  for (const round of history) {
    const item = document.createElement("li");
    item.textContent = `${round.player} vs. ${round.computer} · ${round.outcome}`;
    list.append(item);
  }
}

Render and reset

In play, after renderScore(), call addRound(player, computer, outcome) and renderHistory(). In the reset handler, set history.length = 0 and call renderHistory(). Each render clears the old list, then for…of walks through the records in order. createElement creates each list item. append inserts it into the list. textContent treats the displayed value as text.

script.js · play with history
function play(player) {
  const computer = chooseComputerMove();
  const outcome = decideWinner(player, computer);
  updateScore(outcome);
  renderScore();
  addRound(player, computer, outcome);
  renderHistory();
  result.textContent =
    `You chose ${player}. Computer chose ${computer}. Result: ${outcome}.`;
}

Chapter 8 of 15

Trace a request from browser to server

A teammate needs to explain how a visitor receives the game and where the score is calculated.

Inputs
The address of the game and a click after it has loaded.
Expected output
A request trace that identifies the browser, server, files, and score owner.
Rules
Distinguish delivery of files from execution of rules. Two browsers keep separate scores.

Build it step by step

Read the address in parts

Consider https://game.example/event/index.html. HTTPS names the protocol used to exchange messages over an encrypted connection. game.example is the hostname. /event/index.html is the path. An optional port can follow the host. A URL fragment such as #rules stays in the browser and can scroll to part of a page. The example hostname is illustrative.

Follow the exchange

The internet connects networks that carry data. The web is one service that uses those networks. DNS helps resolve a hostname to an address, often with cached results. The browser connects to the web server and sends an HTTP request. A request like GET asks to retrieve a resource. The response has a status code, headers describing the response, and usually a body. HTML can direct the browser to request more files.

Locate the game’s work

The server delivers the same static assets to each visitor. The browser interprets the HTML, applies CSS, and runs JavaScript. The score changes inside the current page. Since this game sends no rounds back to the server, a shared leaderboard would require a way to send, validate, store, and read common results. Imagine the cost and access decisions that would follow from that new requirement.

Try two independent sessions

Open the final game in two tabs. Play in one tab and inspect the score in the other. This verifies that each page has its own state. Repeat the experiment with Network open after you start the local server in the next lesson.

Chapter 9 of 15

Serve the game locally over HTTP

The team needs to test the same file requests a visitor will make when the game is hosted.

Inputs
The release files, a local server process, and a browser.
Expected output
A working game at a localhost URL and a clean Network trace.
Rules
Serve the public folder. A local loopback address is for the current computer. No account is needed.

Build it step by step

Choose the folder to serve

Open a terminal in rps-git-lab. Confirm that the folder contains public/index.html. The server root is public, so a browser request for /logic.js should read public/logic.js. Python 3 provides a small development server. On Windows use py -3 in place of python3 if that is how Python is installed.

Terminal · in rps-git-lab
python3 -m http.server 8000 --bind 127.0.0.1 --directory public

Observe the difference from a file URL

Open http://127.0.0.1:8000/ in the browser. In Developer Tools → Network, reload with the panel open. Inspect the request for the document and for style.css, logic.js, and script.js. With caching disabled in the panel, a fresh successful request ordinarily shows 200. A 304 means the client may reuse a cached copy after revalidation. Stop the server with Ctrl+C when finished.

Compare where the files come from

Opening public/index.html directly reads local files from disk. Running the Python server sends files through HTTP to your browser. Hosting does similar file delivery from managed infrastructure reached by an internet address, typically through HTTPS. The game still runs the same code in the browser. The server does not need to re-run a deployment each time someone presses Rock.

Rules

Make rule checks repeatable

Rules

Build it step by step

Test the decision before the UI

Open test/game.test.cjs. Node.js runs JavaScript outside the browser. The file uses Node’s built-in test runner and strict equality assertions. It reads and evaluates public/logic.js as a separate script so the test calls the same decideWinner function used by the game. That script has no DOM references. The expected values come from the decision table. An assertion reports a failure if actual and expected values differ.

Terminal · from rps-git-lab with Node.js 22 or newer
node --test

Control randomness

The function accepts a random-number supplier. Pass a function returning a fixed sample to reproduce exactly which index is chosen. Samples at 0, 0.5, and 0.999 hit the three valid indices without hoping a random run happens to cover them. A unit test can verify the return value, while a browser check verifies the visible interaction.

Example assertion · inside a test
assert.equal(chooseComputerMove(() => 0.999), "scissors");

Copy the included .github folder with the repository. The workflow tells GitHub Actions to prepare a clean runner, check out the commit being tested, set up Node 22, and run the same test command. on: [push, pull_request]
